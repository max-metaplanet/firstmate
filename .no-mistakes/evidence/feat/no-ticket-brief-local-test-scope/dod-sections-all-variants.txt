== nm
# Definition of done
Delivery contract: mode=no-mistakes
Ship branch: fm/nm
Run locally only the tests for what you changed, plus affected lint and formatting checks.
Never run or wait on full-suite local hooks (including Husky pre-commit/pre-push suites) or a full monorepo test run.
If such a hook would run, bypass it for that command only with `git -c core.hooksPath=/dev/null commit ...` or an authorized `git -c core.hooksPath=/dev/null push ...`; never disable hooks globally or bypass the no-mistakes gate.
Where this delivery path authorizes you to push a branch that forge CI runs on, finish local iteration and push ONCE per task when ready; no-mistakes owns its push, and local-only never pushes.
A Gerrit `gerrit-axi publish` patch set or an external-review re-upload made to correct the work before reporting done is not a second push and is not reported as blocked, because no forge CI runs on it.
PR CI is the full regression gate for PR delivery; keep CI spend down and never trigger extra CI reruns yourself, including failed-job reruns or manual workflow dispatches.
These worker limits leave no-mistakes' configured test step, repair loop, and `ci.rerun_transient` behavior unchanged.

The implementation is complete only when committed on your branch; the TASK is complete only when the pipeline has turned that commit into a PR with green checks.
As soon as the implementation is committed and your tree is clean, invoke /no-mistakes yourself and drive the run to its outcome: do not report done first, and do not wait for firstmate to send you the pipeline.
The pipeline owns the push; never push from this copy.

For a conflict-only rebase or conflict resolution of an already-open PR, use `FM_HOME=/tmp/fmbrief.osiY ~/.no-mistakes/worktrees/61c6dd39b831/01M5YC9XDE7KDMXVS6AWNG7RXX/bin/fm-pr-refresh.sh prepare nm <pr-url>` before any push or pipeline refresh; its header owns classification, publication wrapping, and the firstmate-controlled ready call.
In direct-PR mode, pass the publication command after `--` to that helper; in no-mistakes mode, prepare first and let the pipeline publish.
This hold overrides the ordinary ready/done instructions below: keep the draft and declared wait until firstmate explicitly asks for the helper's `ready` call.
Do not report done or mark it ready while `state/nm.pr-refresh` exists.
Follow the CI-round policy in validation-supervision; never hand-fix or push around the pipeline's repair loop.
When a required check is red, read its failure log.
Never push an empty, no-op, or "retrigger" commit to rerun CI.
When no-mistakes owns CI, report unrelated failures through its CI step; its "skip as unrelated with evidence" path remains valid.
As soon as the pipeline opens its PR, read it by its full URL.
If it is a draft, confirm the pipeline's local review, test and lint steps passed and the work is ready, then mark it ready using the forge command below BEFORE waiting for CI green.
A draft-skipping workflow needs that ready transition to run its full suites; skipped draft checks alone never prove the ready PR green.
If this head's checks were skipped while it was draft, require fresh results from the workflows the ready transition triggers on this head before treating CI as green; otherwise completed, non-skipped results on this same head count. When checks were skipped while draft, read the ready time with `gh api --paginate repos/<owner>/<repo>/issues/<number>/timeline --jq '.[] | select(.event == "ready_for_review") | .created_at' | tail -n 1` and wait with `~/.no-mistakes/worktrees/61c6dd39b831/01M5YC9XDE7KDMXVS6AWNG7RXX/bin/fm-pr-checks.sh --watch --after <ready time> <pr-url>`, so no check skipped before the ready transition counts.
Your only `done:` is the CI-ready line below, and a ship `done:` naming no PR is refused rather than recorded, because the work is not shipped.

You drive no-mistakes by responding to its gates, not by implementing fixes.
Follow the guidance no-mistakes itself provides for the mechanics: it loads when you invoke /no-mistakes, and `no-mistakes axi run --help` plus the `help` lines in each `axi` response are authoritative and version-matched to the installed binary.
When starting no-mistakes, pass `--intent` as only this brief's `## Captain's intent` subsection body, not its heading, plus any later words the captain actually said.
Preserve the actual words without adding speaker labels or direct address; the subsection heading supplies provenance outside the pipeline input.
For a legacy brief with no such subsection, include only words on lines marked `[captain] `, excluding that metadata prefix; never copy its mixed `# Task` wholesale.
If it has no provenance-marked captain words, stop and ask firstmate instead of starting no-mistakes.
Do not include `## Firstmate spec`, later Firstmate build constraints, or your own decisions and tradeoffs.
The `--intent` string you pass must be self-sufficient: that string plus the codebase must let a reader reconstruct roughly the same specification, without depending on a separate report, a PR, or context that lives only in this conversation.
When the captain's intent refers to a report, decision, or PR ("do items 1, 2, 3, and 7 of the report"), write the substance of the referenced items into `--intent` in the captain's terms, not only the pointer; that substance is the captain's ask by reference, while Firstmate's build instructions and your own decisions still stay out.
This replaces the no-mistakes skill's advice to enrich `--intent` with decisions and tradeoffs; that advice does not apply to Firstmate-dispatched work.
Do not hand-edit, commit, or fix findings yourself while a run is active - the pipeline applies every fix.

1. `git remote get-url origin` - the `<owner>/<repo>` it names is your PR target, and `origin` is the only remote you push to.
2. `git symbolic-ref --quiet --short refs/remotes/origin/HEAD` - drop the leading `origin/` for your base branch; when it prints nothing, read the `HEAD branch:` line of `git remote show origin`. When the Delivery contract above names a base branch, use that branch instead of the default.

A draft cannot be merged, so a done report on one leaves the merge unasked.
Then append `done [at=<epoch>]: PR {url}` to the status file and stop.
That `done:` is accepted only when the PR is on the repository `origin` names and this copy's HEAD - your latest commit - is pushed to your PR branch; the check tests that commit, not merely that a branch moved.
A PR raised on any other repository is refused rather than recorded, so if the target you resolved is not the one you expected, append `blocked [at=<epoch>]: {what origin names}` instead of opening it.
If you deliberately keep the PR a draft, append `paused [at=<epoch>]: {why the draft is held}` instead of done.
Do NOT run /no-mistakes. The configured merge authority decides whether to merge the PR; firstmate relays the outcome.

When it is implemented and committed, publish it.
Publish from this copy with `gerrit-axi`, never with `git push`:
1. Run `git fetch origin` so the server's branch tip is in this repository; `gerrit-axi` reads its base off the server and refuses when that tip is not here.
2. Run `gerrit-axi publish --squash --json`, adding `--branch <b>` only when the task names a target branch other than the server's default.
   It is one push to `refs/for/<branch>` that turns every commit since your branch left the server's branch into ONE change carrying the oldest commit's message, so that message is the review description: make it the one you want reviewed.
   It keeps any `Change-Id` a commit already carries and stamps one into the oldest commit when it has none, rewriting your local branch's messages only.
   Never edit, remove, or regenerate a `Change-Id`: a different one creates a different change and orphans the first one's review, while the same one adds a patch set to it.
   Never pass `--stack`: a stack of changes is not published from this fleet until it can be watched by its membership pinned when its watch is armed, and the watch follows exactly one change.
3. Read the record it prints: `ok` must be `true`, and the one row of its `changes` table is your change. Its `url` is the change URL; when `url` is null, write `https://<host>/c/<project>/+/<change>` from your `origin` remote's host and that row's `project` and `change`.
   A failure prints a typed error record instead; fix what it names and publish again, which updates the same change rather than creating another.
Then append `done [at=<epoch>]: PR {change url} published for review` to the status file and stop. You are finished.
That `done:` is accepted only when the change's current patch set on the server carries this copy's HEAD tree, so commit nothing after publishing; if you must change the work, commit it and publish again before reporting done.
A `done:` whose URL is not the canonical `https://<host>/c/<project>/+/<number>` change URL is refused.
There is no pull request, no `gh-axi` call, and no forge CI result to report: a human reviewer approves and submits the change on the server, and firstmate relays that outcome.
Do NOT run /no-mistakes.
